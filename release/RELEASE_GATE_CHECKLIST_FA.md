# چک‌لیست دروازه انتشار Mazand FOS

این چک‌لیست فقط وقتی «قبول» است که برای هر مورد شاهد قابل بازبینی ثبت شده باشد. وجود مستندات به‌تنهایی اثبات نمی‌کند نرم‌افزار پیاده‌سازی یا آزمایش شده است.

## ۱. حاکمیت و آماده‌سازی
- [ ] نسخه/برچسب انتشار، commit دقیق و شاخه منبع مشخص است.
- [ ] تغییرات از شاخه کاری و Pull Request آمده‌اند؛ تغییر مستقیم main انجام نشده است.
- [ ] ماتریس ردیابی نیاز ← کد ← آزمون ← شاهد تکمیل شده است.
- [ ] تغییرات داده، سازگاری عقب‌رو و تصمیم‌های معماری بازبینی شده‌اند.
- [ ] مجوز صریح صاحب پروژه برای انتشار/انتشار عمومی یا خصوصی ثبت شده است.

## ۲. مالی و بازرگانی
- [ ] ثبت سند قطعی بدون توازن بدهکار/بستانکار ممکن نیست.
- [ ] سند قطعی با حذف/ویرایش خاموش بازنویسی نمی‌شود؛ اصلاح از مسیر برگشت/اصلاحیه و ردپا انجام می‌شود.
- [ ] شرط پرداخت، ابزار، رویداد خزانه، تخصیص و سند حسابداری مستقل‌اند و اثر دوباره ندارند.
- [ ] پرداخت جزئی/ترکیبی، پیش‌پرداخت، اضافه‌پرداخت، برگشت، چک و مانده تخصیص‌نیافته آزمایش شده‌اند.
- [ ] صافی بارفروش چندبار/چندباربرگ، اختلاف وزن، کارمزد نسخه‌دار و هزینه/واریزی ریزشده را پوشش می‌دهد.
- [ ] صورت‌حساب طرف حساب و مانده معین با دفتر کل آشتی‌پذیر است.
- [ ] کارمزد بانکی، انتقال بین حساب‌های خودی، چک در گردش و اقلام تطبیق‌نیافته دوباره‌شماری نمی‌شوند.

## ۳. وزن، انبار و تولید
- [ ] وزن باسکول، تعداد سبد، وزن خالی هر سبد، پایه وزن، افت درصدی/کیلوگرمی و وزن قابل‌صورتحساب مستقل و قابل ردیابی‌اند.
- [ ] تغییر آخرین فیلد افت، فیلد مشتق دیگر را طبق قرارداد به‌روز می‌کند.
- [ ] محصول، درجه/کیفیت، سبد، واحد، انبار و تاریخ اثر در ردیف مستند است.
- [ ] فروش به‌عنوان خروج ثبت می‌شود، نه ضایعات منفی؛ مغایرت وزن پنهان یا خودکار به سند حسابداری تبدیل نمی‌شود.
- [ ] برگشت، ضایعات، اصلاح موجودی، حواله/انتقال و ارتباط سند منبع پوشش داده شده‌اند.

## ۴. UX و داده
- [ ] فرم‌های پرتکرار در نمای اصلی کار می‌شوند؛ نوار اقدام ثابت و پیمایش داخلی جدول وجود دارد.
- [ ] ایجاد سریع طرف‌حساب/محصول/حساب/سبد فرم والد و داده‌های پیش‌نویس را حفظ می‌کند.
- [ ] عملیات آیکونی راهنمای فارسی و وضعیت فوکوس/صفحه‌کلید دارند.
- [ ] پیش‌نمایش ورود اکسل، نگاشت ستون، تکراری‌ها، اعتبارسنجی و نتیجه خط‌به‌خط آزموده شده‌اند.
- [ ] خروجی واقعاً در نسخه هدف Office 2013 باز و فرمول‌ها محاسبه شده‌اند؛ سازگاری صرفاً از روی کد ادعا نشده است.

## ۵. همگام‌سازی و امنیت
- [ ] کارکرد بدون اینترنت در سناریوهای منتخب آزمون شده است.
- [ ] شناسه پایدار، outbox/inbox، تکرارپذیری امن، حذف نرم و صف تعارض آزمایش شده‌اند.
- [ ] همزمانی دو کاربر، قطع برق/شبکه هنگام ثبت و ارسال تکراری درخواست بررسی شده‌اند.
- [ ] پایگاه SQLite قابل‌نوشتن به‌صورت فایل مشترک روی LAN استفاده نشده است.
- [ ] نقش/مجوز، رویدادهای حساس، مدیریت رازها و محدودیت دسترسی آزموده شده‌اند.
- [ ] پشتیبان، checksum و آزمون واقعی بازیابی وجود دارد.

## ۶. نصب، انتشار و بازگشت
- [ ] ساخت پاک از منبع و ساخت/اجرای تست‌ها روی محیط هدف مستند شده است.
- [ ] مهاجرت پایگاه داده و مسیر ارتقا/بازگشت آزمایش شده‌اند.
- [ ] نصب/حذف، شروع سرویس، مجوز پوشه‌ها، مسیر داده، log و خطاهای قابل فهم بررسی شده‌اند.
- [ ] زمان‌بندی backup، مقصد بیرونی و آزمون restore انجام شده‌اند.
- [ ] بسته انتشار شامل نسخه، changelog، checksum، دستور نصب، محدودیت‌ها و rollback است.
- [ ] داده شخصی/مشتری/بانکی و secret در مخزن/بسته نیست.
- [ ] smoke test پس از نصب و تأیید نهایی کاربر انجام شده است.

## شاهد اجباری برای هر مورد
شناسه آزمون/فرمان، محیط و نسخه، نتیجه واقعی، log/تصویر یا فایل خروجی، تاریخ و شخص اجراکننده. هر مورد اجرا نشده باید «اجرا نشده» بماند؛ آن را «قبول» علامت نزنید.
