# قرارداد مشارکت و تغییر

1. پیش از هر تغییر، `docs/26_GITHUB_CHANGE_CONTROL_FA.md` و `prompts/22_CHANGE_IMPACT_REGRESSION_FA.md` را بخوانید.
2. کار را در branch کوتاه‌عمر و نام‌گذاری‌شده مانند `docs/audit-report`, `feat/citrus-invoice-weights`, `fix/bank-match-idempotency` انجام دهید.
3. در هر PR، مسئله، نیازمندی‌های مرتبط، فایل‌ها/ماژول‌های متاثر، مهاجرت داده، تست‌ها، شواهد و روش rollback را بنویسید.
4. تغییر کد مالی/موجودی بدون تست‌های محاسباتی و رگرسیون پذیرفته نیست.
5. تغییر قرارداد داده باید migration، نسخه schema، تست رفت‌وبرگشت یا استراتژی بازیابی داشته باشد.
6. طراحی بصری باید screenshot در حداقل پنجره‌های مصوب، RTL، خطا/empty/loading و نمونه داده مصنوعی داشته باشد.
7. تست اجرا نشده را Pass اعلام نکنید؛ وضعیت `NOT RUN` مجاز است.
8. main فقط از مسیر PR و پس از Gateهای تعریف‌شده قابل تغییر است.
