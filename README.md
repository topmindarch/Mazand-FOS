# Mazand FOS — بسته جامع مشخصات، دستورهای اجرا و انتشار (FA v4)

> این بسته «مشخصات محصول + قرارداد فنی + کتابخانه پرامپت + کنترل‌های پذیرش و انتشار» است؛ خودِ نرم‌افزار اجرایی یا اثبات پیاده‌سازی نیست. هر قابلیت تنها بعد از بررسی کد، اجرای آزمون و ارائه شواهد می‌تواند Done اعلام شود.

## شروع دقیق
1. `00_START_HERE_FA.md` را بخوانید.
2. `docs/01_DECISION_REGISTER_AND_EVIDENCE_FA.md` را به‌عنوان خط مبنای تصمیمات بخوانید.
3. مستندات تخصصی `docs/` را قبل از هر کدنویسی مرور کنید.
4. در عامل کدنویسی، ابتدا فقط `prompts/00_GLOBAL_CONTRACT_FA.md` و سپس `prompts/01_READ_ONLY_AUDIT_FA.md` را اجرا کنید. در مرحله ممیزی هیچ تغییری در کد یا تنظیمات ایجاد نمی‌شود.
5. بر اساس خروجی ممیزی، `prompts/02_TRACEABILITY_AND_GAP_ANALYSIS_FA.md` را اجرا کنید؛ سپس فقط طبق ترتیب `prompts/INDEX_FA.md` پیش بروید.

## داخل بسته
- خط مبنای اصلی قبلی (اسناد بلند v0.4 و v1.0، پرسش‌نامه خام، تفسیر دور دوم و runbook قبلی) در `source-baseline/` بدون ادعای جایگزینی نگهداری شده است.
- 21 سند تکمیلی تخصصی در `docs/`، شامل کدینگ حساب، مدل پرداخت/تخصیص، صافی بارفروش، وزن مرکبات، دفترکل، بانک/چک، فرهنگ داده، کاتالوگ فرم‌ها، ماتریس اثر حسابداری و روش Bootstrap عامل.
- 17 پرامپت ترتیبی مستقل + runbook پیوسته، قالب traceability و execution log، کاتالوگ پذیرش، 3 طرح SVG از داشبورد/فاکتور/کدینگ حساب، design tokens و release gates.

## اصولی که قابل مذاکره‌ی خاموش نیستند
- ممیزی فقط‌خواندنی پیش از تغییر؛ حفظ تاریخچه Git و فایل‌های موجود؛ عدم کار مستقیم روی `main`.
- هیچ ورود به محیط واقعی و هیچ push/release/انتشار بدون مجوز صریح مالک.
- داده مشتری، بانک، اطلاعات شخصی، کلیدها، فایل DB واقعی و نسخه پشتیبان کسب‌وکار نباید وارد GitHub یا prompt عمومی شوند.
- بدهکار/بستانکار قطعی باید متوازن باشد؛ پیشنهاد ثبت یا Match بانکی تا تأیید کاربر صرفاً پیشنهاد است.
- فروش، دریافت وجه، انتقال وجه، صدور چک و تخصیص پرداخت رویدادهای مجزا هستند؛ اثر دوباره ممنوع.
- نبود داده نباید به‌عنوان صفر جعل شود؛ هر اختلاف یا تعارض قابل مشاهده و پیگیری است.
- نمایش تومان فقط تبدیل نمایشی ثابت 10 ریال = 1 تومان است؛ مقدار مرجع ریال است.

## وضعیت اعتبارسنجی
این بسته بر اساس اسناد موجود در محیط بازسازی شده است. تولید ZIP، شمارش محتوا، صحت JSON/SVG و integrity آرشیو پس از ساخت با ابزارهای محلی بررسی می‌شود. این بررسی، آزمون نرم‌افزار ERP نیست و به‌تنهایی هیچ قابلیت اجرایی را تأیید نمی‌کند.
